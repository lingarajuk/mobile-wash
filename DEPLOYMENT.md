# 🚀 AquaGo Wash - Production Cloud Deployment Guide

This guide details the step-by-step procedure to deploy the complete AquaGo Wash system to **Railway** (MySQL + FastAPI Backend) and **Vercel** (Customer, Worker, Admin Web Apps).

---

## 📋 STEP 1: Deploy MySQL on Railway

1. Go to [railway.com](https://railway.com) and create a **New Project**.
2. Click **+ New Service** -> Select **Database** -> **Add MySQL**.
3. Railway will provision a managed MySQL instance with a private connection string (`MYSQL_URL`).
4. Note the database variables generated by Railway:
   - `MYSQLHOST` / `DB_HOST`
   - `MYSQLPORT` / `DB_PORT`
   - `MYSQLDATABASE` / `DB_NAME`
   - `MYSQLUSER` / `DB_USER`
   - `MYSQLPASSWORD` / `DB_PASSWORD`
   - `DATABASE_URL` (or `MYSQL_URL`)

---

## 📋 STEP 2: Deploy Shared FastAPI Backend on Railway

1. In the same Railway project, click **+ New Service** -> **GitHub Repo** -> select `lingarajuk/mobile-wash`.
2. In the **Service Settings**:
   - **Root Directory**: Leave blank (uses root `railway.json` and `backend/Dockerfile`)
   - **Healthcheck Path**: `/health`
3. Add the following **Environment Variables** in Railway:

| Variable Name | Example / Production Value | Notes |
|---|---|---|
| `DATABASE_URL` | `${{MySQL.DATABASE_URL}}` *(or Railway MySQL connection string)* | Shared MySQL connection |
| `DB_HOST` | `${{MySQL.MYSQLHOST}}` | MySQL Host |
| `DB_PORT` | `${{MySQL.MYSQLPORT}}` | MySQL Port (3306) |
| `DB_NAME` | `${{MySQL.MYSQLDATABASE}}` | Database Name |
| `DB_USER` | `${{MySQL.MYSQLUSER}}` | Database User |
| `DB_PASSWORD` | `${{MySQL.MYSQLPASSWORD}}` | Database Password |
| `JWT_SECRET_KEY` | `aquago_prod_jwt_supersecret_key_2026_98472918` | Generate a secure secret |
| `CORS_ORIGINS` | `https://aquago.vercel.app,https://aquago-worker.vercel.app,https://aquago-admin.vercel.app` | Updated with Vercel URLs |
| `CLOUDINARY_URL` | *(Optional)* `cloudinary://api_key:api_secret@cloud_name` | Cloud storage for photos |

4. Click **Deploy**. Railway will run `seed.py` and database migrations (`migrate_db.py`, `migrate_db_v2.py`) automatically upon startup.
5. In **Networking**, click **Generate Public Domain** to get your backend URL (e.g. `https://aquago-api-production.up.railway.app`).
6. Test backend health:
   ```bash
   curl https://<YOUR_RAILWAY_URL>/health
   ```
   **Expected Response**:
   ```json
   {
     "status": "healthy",
     "project": "AquaGo Mobile Water Wash API",
     "version": "1.0.0",
     "database": "connected"
   }
   ```

## 📋 STEP 3: Deploy Customer Web App on Vercel

1. Go to [vercel.com](https://vercel.com) -> **Add New Project** -> Import `lingarajuk/mobile-wash`.
2. Configure Project Settings:
   - **Project Name**: `aquago-customer`
   - **Framework Preset**: `Vite`
   - **Root Directory**: `apps/customer` (or use `./` with Build Command: `npm run build:customer` and Output: `dist/customer`)
   - **Build Command**: `npm run build:customer`
   - **Output Directory**: `dist/customer`
3. Add **Environment Variables**:
   - `VITE_API_URL`: `https://<YOUR_RAILWAY_BACKEND_URL>/api/v1`
4. Click **Deploy**.

## 📋 STEP 6: Configure CORS on Backend

After obtaining the live Vercel URLs:
1. In Railway, update the `CORS_ORIGINS` variable on the Backend service with all three Vercel URLs:
   ```text
   CORS_ORIGINS=https://aquago-customer.vercel.app,https://aquago-worker.vercel.app,https://aquago-admin.vercel.app
   ```
2. Redeploy backend (instant restart).

## 🔒 Security & SPA Routing Verification

- **Direct Route Navigation**: Each web app contains `vercel.json` with wildcard SPA rewrites (`"source": "/(.*)", "destination": "/index.html"`), ensuring URLs like `/my-bookings/AGN-87217` or `/admin/bookings/AGN-87217` do not throw 404 errors on browser reload.
- **Role-Based Access Control**: Backend middleware strictly verifies JWT tokens against `User.role` on `/api/v1/admin/*` and `/api/v1/employees/*`.
- **Database Safety**: Schema migrations use `CREATE TABLE IF NOT EXISTS` and `ALTER TABLE ... ADD COLUMN` guards to prevent data loss or duplicate index collisions.
